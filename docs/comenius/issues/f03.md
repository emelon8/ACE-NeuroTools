## Status and source

**Planning draft — human decisions required.** Suggested ownership role: Configuration + UX owner; no person is assigned. Proposed stage: First path.

Meeting: replace mandatory CSV editing with GUI configuration while retaining reproducibility and CLI access.

## What to build

Load an existing supported CSV/JSON configuration or a new experiment, edit meaningful processing parameters in a form, save a named revision, and use the same effective settings from the CLI.

## Acceptance criteria

- [ ] Relevant fields show labels, units, defaults, valid ranges/relationships, and the source of inherited or overridden values.
- [ ] A supported legacy example imports without changing source files; duplicate IDs, conflicting values, and unsupported fields are reported.
- [ ] Save/reopen preserves explicit values and defaults according to a versioned precedence contract; any export limitations are documented.
- [ ] GUI and CLI produce the same normalized effective configuration for a nominated fixture.
- [ ] The researcher can review edits before saving, discard a draft, and avoid silently overwriting a newer revision.
