## Status and source

**Planning draft — human decisions required.** Suggested ownership role: Data reader + UX owner; no person is assigned. Proposed stage: First path.

Meeting: recognize and parse supplied data, associate it with the selected experiment.

## What to build

Attach one supported recording to an existing experiment. Present detected modality/format, relevant metadata, and evidence, then let the researcher confirm or correct the choice before the input is recorded.

## Acceptance criteria

- [ ] A nominated real recording and a synthetic fixture can be selected from the GUI and inspected through the CLI.
- [ ] Detection reports supported format, matching evidence, companion files, missing metadata, and any competing matches.
- [ ] Unknown, incomplete, or ambiguous inputs have a clear recovery path; manual override is explicit and recorded.
- [ ] The chosen copy/reference policy is visible, raw content is preserved, and duplicate or moved input handling is tested.
- [ ] Accepted import records input identity and the human’s experiment association without silently creating an experiment.
