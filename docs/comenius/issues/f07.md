# Compare experiment revisions and restore settings without losing history

## Status and source

**Planning draft — human decisions required.** Suggested ownership role: History + provenance owner; no person is assigned. Proposed stage: Trust and usability.

Meeting: continuous record of experiment edits, inspect change over time, recover lost settings.

## What to build

Let a researcher see saved revisions, compare meaningful settings, and restore an older configuration into a new revision while keeping existing runs traceable.

## Acceptance criteria

- [ ] History shows the agreed author/time/reason metadata and human-readable changes, including imported values and effective defaults.
- [ ] A reviewer compares two revisions without decoding raw serialized files.
- [ ] Restoring an earlier revision creates a new revision and preserves the prior revision and its run/result links.
- [ ] Changed/missing input references or unavailable module versions are surfaced before rerunning a restored revision.
- [ ] CLI users can inspect/restore equivalent revisions; stale concurrent writes and the agreed retention/deletion policy have explicit behavior.
