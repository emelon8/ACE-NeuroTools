## Status and source

**Planning draft — human decisions required.** Suggested ownership role: Onboarding + documentation owner; no person is assigned. Proposed stage: First path.

Meeting: first-use setup flow, checks, examples, and optional integrations without overwhelming users.

## What to build

Guide a new researcher from installation/launch to a configured example project, with dependency checks, clear explanations, and a path to use their own recording.

## Acceptance criteria

- [ ] A first-time user can run the agreed setup checklist, select a project location, and launch the documented example path.
- [ ] Missing dependencies and unsupported environments show actionable remedies; any installation or external transfer requires the agreed explicit action.
- [ ] Tutorial/example data is clearly identified, has documented availability/permissions, and cannot silently become the user’s real experiment metadata.
- [ ] Users can skip/revisit help and optional integrations; keyboard operation and readable labels/units are reviewed with target users.
- [ ] The walkthrough reuses the shared project/import/configuration operations and has an equivalent CLI route.
