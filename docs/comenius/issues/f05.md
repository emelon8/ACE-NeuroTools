## What to build

Execute one approved miniscope run using the existing processing pipeline while keeping the interface responsive. Show progress and actionable failures, retain the run record, and let a researcher deliberately cancel or retry.

## Acceptance criteria

- [ ] One nominated recording completes the agreed processing steps from GUI and CLI using the same saved plan.
- [ ] Long processing runs outside the UI event loop and reports stage/log updates without invented percentage or time estimates.
- [ ] Success, failure, cancellation, and interruption are distinguishable and retained, including partial-artifact status.
- [ ] Cancellation releases worker resources and never advertises incomplete results as complete; retry creates a linked attempt.
- [ ] Reopening after interruption shows the actual durable outcome; a prior run’s artifacts are not silently overwritten.
