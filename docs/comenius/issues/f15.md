## What to build

Publish a contributor path that makes issue claiming, design decisions, module proposals, scientific review, and acceptance demonstrations understandable to a newcomer.

## Acceptance criteria

- [ ] A contributor guide explains claim → named owner → agreed contract → linked PR → human demonstration → closure.
- [ ] Issue/PR templates capture scope, affected decisions/dependencies, tests or validation evidence, and scientific review needs.
- [ ] Maintainers agree reviewers for scientific changes, shared interfaces, and releases; names are filled only with their agreement.
- [ ] A reference contribution walkthrough points to the module contract when available and explains fixtures, docs, attribution, and licensing expectations.
- [ ] A newcomer dry-runs finding and claiming a bounded task; unresolved decisions remain visible and do not get an agent-ready label.

## Blocked by

None — discovery/design can start immediately; resolve the decision gates before implementation.

Blockers govern completion/integration. Research, fixtures, and design can proceed in parallel against an agreed contract.
