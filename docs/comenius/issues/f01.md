## Status and source

**Planning draft — human decisions required.** Suggested ownership role: Application + UX owner; no person is assigned. Proposed stage: First path.

Meeting: project hierarchy, explicit new/existing experiment choice, GUI-led workflow, CLI parity.

## What to build

Deliver the first small application path: a researcher creates a project and experiment in the GUI, closes the application, reopens the same workspace, and inspects the same saved identity through the CLI. Define the shared application contract through this working slice.

## Acceptance criteria

- [ ] The GUI offers open/create project and existing/new experiment with explicit destination confirmation.
- [ ] Stable identities survive renames and reopening; names, location, and experiment ownership remain understandable.
- [ ] A minimal saved experiment can be created/read through shared application operations from both interfaces, with equivalent validation.
- [ ] Cancelled creation does not leave a misleading complete experiment; duplicate names/IDs, missing locations, and stale conflicting writes follow the agreed policy.
- [ ] A researcher demonstrates create → close → reopen; a compatibility check preserves the existing CLI entry points.

## Blocked by
