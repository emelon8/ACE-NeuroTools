## Status and source

Meeting: catch problems before expensive processing and show a confirmation summary.

## What to build

Prepare an inspectable run plan from a saved configuration, perform bounded checks, and require human approval of that plan before dispatch. Offer equivalent structured preflight results and explicit approval behavior for CLI use.

## Acceptance criteria

- [ ] Summary includes experiment, inputs, selected steps, effective settings, output destination, available environment details, and any planned human checkpoints.
- [ ] Checks catch missing/unreadable inputs, required metadata, invalid parameters, missing dependencies, output conflicts, and relevant disk/resource concerns before expensive processing.
- [ ] Checks distinguish blocking errors, acknowledgeable warnings, and unknown estimates; they do not claim to guarantee scientific correctness or run success.
- [ ] Inputs/configuration changes invalidate stale preflight and approval; dispatch verifies that it consumes the approved plan.
- [ ] A bounded optional sample/dry-run check is labelled with cost and limitations; CLI non-interactive approval follows the agreed recorded policy.
