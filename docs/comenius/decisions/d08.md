# D08 — Reproducibility contract

GitHub: https://github.com/emelon8/experiment_analysis/issues/94

## Parent

https://github.com/emelon8/experiment_analysis/issues/69

## Decision to make

What evidence must travel with a result, and what level of repeatability can we claim?

**Status: open — a human decision is required.** The recommendation below is a planning proposal, not an accepted implementation choice.

**Suggested participants:** Scientific reviewer + application maintainer. No person is assigned. **Resolve:** Before run contract.

## Context

Area: Auditability. This topic comes from the Comenius planning synthesis of the supplied meeting and project brief. See the [decision register](https://github.com/emelon8/experiment_analysis/blob/proj-comenius/docs/comenius/decisions.md#d08) for the shared snapshot.

## Options

1. Configuration only.
2. inputs/configuration/software/environment plus review history.
3. byte-identical outputs across machines.

## Recommendation

Record effective settings, input identities/checksums, software and module versions, relevant environment/hardware, seeds when applicable, human choices, status, logs, and output identities. Distinguish a traceable rerun from byte-identical reproduction.

## Trade-offs and questions to resolve

Choose hashing depth/cost for large datasets, external dependency capture, and numerical comparison tolerances. A settings file alone cannot establish full reproducibility.
