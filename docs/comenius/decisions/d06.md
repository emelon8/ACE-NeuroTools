# D06 — Data layout and ownership

GitHub: https://github.com/emelon8/experiment_analysis/issues/92

## Parent

https://github.com/emelon8/experiment_analysis/issues/69

## Decision to make

Does “all in one place” mean copying recordings, linking them, or offering both?

**Status: open — a human decision is required.** The recommendation below is a planning proposal, not an accepted implementation choice.

**Suggested participants:** Data steward + application maintainer. No person is assigned. **Resolve:** First.

## Context

Area: Persistence. This topic comes from the Comenius planning synthesis of the supplied meeting and project brief. See the [decision register](https://github.com/emelon8/experiment_analysis/blob/proj-comenius/docs/comenius/decisions.md#d06) for the shared snapshot.

## Options

1. Copy into a managed project.
2. reference external/NAS data.
3. explicit copy-or-reference choice.

## Recommendation

Organize manifests and per-run results under the experiment; allow explicit references to large raw recordings, with optional import by copy. Make missing/moved-data repair visible.

## Trade-offs and questions to resolve

Raw data can be very large. Define duplicate detection, rename/relocation behavior, writable output roots, and whether two projects may refer to one input. The physical layout follows D02.
