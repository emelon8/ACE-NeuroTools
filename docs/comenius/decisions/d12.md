# D12 — Execution, resources, and interruption

## Parent

https://github.com/emelon8/experiment_analysis/issues/69

## Decision to make

Where do expensive runs execute, and what does stopping or recovering one mean?

**Status: open — a human decision is required.** The recommendation below is a planning proposal, not an accepted implementation choice.

**Suggested participants:** Compute maintainer + lab users. No person is assigned. **Resolve:** Before execution.

## Context

Area: Runtime. This topic comes from the Comenius planning synthesis of the supplied meeting and project brief. See the [decision register](https://github.com/emelon8/experiment_analysis/blob/proj-comenius/docs/comenius/decisions.md#d12) for the shared snapshot.

## Options

1. One local job.
2. a local queue.
3. remote/HPC/Slurm workers or a hosted service.

## Recommendation

Start with one local worker process, responsive UI, stage progress, cancellation, and retained failure records. Record an interrupted run on restart; make retry a new linked run.

## Trade-offs and questions to resolve

Automatic resumption requires reliable checkpoints and compatible intermediate artifacts; do not promise it by calling a retry “resume.” Set CPU/memory/disk policies and concurrency behavior.
